## 🧩 Agrupación por Característica (Feature-Based Grouping)

En lugar de agrupar archivos por su tipo (/services, /components, /hooks), agrupas los archivos por la característica o dominio de negocio al que pertenecen.

Esto tiene la gran ventaja de la cohesión: si tienes que trabajar en todo lo relacionado con el "Registro" (signup), sabes que todo lo que necesitas (el componente, el hook para el formulario, el servicio API) está en una sola carpeta.

## Estructura Recomendada para Next.js

Para mantener la estructura del App Router de Next.js (app/) intacta para las rutas y aún así beneficiarte de la agrupación por característica, el lugar ideal para tus módulos de dominio sería en la raíz de src.

En lugar de tener /services, tendrías carpetas como /features o /domains.

### Opción A: Carpeta features (Más común en frontend)

bash ```
src/
├── app/
│   ├── (auth)/
│   │   ├── login/
│   │   ├── signup/
│   │   └── ...
│   └── ...
├── features/  <-- Nueva carpeta de agrupación por característica
│   ├── signup/
│   │   ├── components/
│   │   │   └── SignupForm.tsx
│   │   ├── hooks/
│   │   │   └── useSignupForm.ts
│   │   └── SignupService.ts  <-- Tu lógica de API
│   ├── auth/
│   │   ├── AuthService.ts  <-- Tu lógica de API
│   │   └── AuthProvider.tsx
│   └── user-profile/
│       ├── components/
│       ├── hooks/
│       └── UserService.ts
└── ...
```
